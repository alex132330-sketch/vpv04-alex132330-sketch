# vpv04-alex132330-sketch

## 1) Что это

Учебный репозиторий, созданный в рамках курса «Профессия вайб-кодер 2.0» (Модуль 1, урок VPa03) для освоения базовых инструментов Git и GitHub. В проекте демонстрируется инициализация локального репозитория, создание осмысленной истории коммитов и публикация кода на GitHub.

## 2) Как запустить

1. Склонируйте репозиторий на свой компьютер:
   ```bash
   git clone https://github.com/alex132330-sketch/vpv04-alex132330-sketch.git
   ```
2. Перейдите в папку проекта:
   ```bash
   cd vpv04-alex132330-sketch
   ```
3. Убедитесь, что у вас установлен Python 3.
4. Запустите основной файл:
   ```bash
   python main.py
   ```

## 3) Как проверить, что работает

После запуска команды `python main.py` в консоли должно появиться:

```
Привет! Это мой первый проект на Git.
Учусь делать осмысленные коммиты!
```

Примеры входных данных также можно посмотреть в файле `examples/hello1.txt`.

## 4) Что я сделал(а) в этом уроке

- Установил Git и настроил имя пользователя и email через `git config --global`.
- Создал локальный репозиторий командой `git init`.
- Сделал несколько осмысленных коммитов с понятными сообщениями (каждый коммит — один логический шаг).
- Подключил локальный репозиторий к удалённому на GitHub через `git remote add origin` и выполнил `git push`.
- Оформил README.md по шаблону курса и добавил папку `examples/` с примером входных данных.

## 5) Что было сложным / что понял(а)

Поначалу было непривычно разделять `git add` и `git commit`, но теперь я понимаю разницу: `add` — это подготовка изменений к коммиту (индекс), а `commit` — их фиксация в истории проекта. Также я осознал, что обычное сохранение файла (`Ctrl+S`) и коммит — это разные вещи: коммит сохраняет снимок всего проекта с контекстом (кто, когда и зачем), а не только текущее состояние одного файла. Теперь я воспринимаю Git как «машину времени» для кода, к которой всегда можно откатиться.
